# ADR-008: 内存管理架构 — Allocator 与 GC 分层

- 状态: 已接受 (2026-11-02)
- 决策者: aserjoker（项目负责人） + CodeAgent
- 关联: ADR-002（GC 抽象）、ADR-007（开发规范）

## 背景

需要统一的内存分配与销毁机制，同时与 GC 明确分层。

## 决策

### 1. Allocator 与 GC 分层

- **Allocator（统一分配器）= 基础设施层**：实际的内存分配/释放。
  通过一个统一的 `Allocator` 类提供分配/释放接口，统一内存入口。
- **GC（垃圾回收）= 业务层**：跟踪 Value 是否可以销毁，
  决定「何时该回收」，基于可达性分析。
- **依赖方向：GC → Allocator**（GC 调用 Allocator 分配/释放；Allocator 不依赖 GC）。

### 2. 职责边界

- **GC**：负责对象图可达性分析、标记/回收的**业务决策**（哪些 Value 可销毁）。
- **Allocator**：负责**实际内存的分配与释放**（内存从哪里来、到哪里去）。

### 3. 收益

- Allocator 可独立替换（池化/arena/malloc 包装），GC 不改。
- GC 可独立演进（Mark-Sweep → 分代/增量），Allocator 不改。
- 统一内存入口便于统计/对齐/调试/内存跟踪。
- 可嵌入友好：宿主可提供自己的 Allocator（回调接口）。

## 后果

- 优点：分层清晰、可替换、统一内存入口、宿主可注入分配器。
- 缺点：多一层间接；需定义清晰的分配/释放接口约定。
