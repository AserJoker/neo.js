# ADR-013: 闭包与作用域模型 — 函数孤立化 + 三层作用域

- 状态: 已接受 (2026-11-02)
- 决策者: aserjoker（项目负责人） + CodeAgent
- 关联: ADR-011（Engine 组织）、ADR-012（Scope 树与 GC）、ADR-001（Sema 闭包收集）

## 背景

确定闭包的处理机制，解决定义函数作用域销毁后闭包变量保活的问题。

## 决策

### 1. 函数持有一个「闭包作用域」（closure_scope）

- 函数对象持有 closure_scope，其 parent 是**定义词法作用域的 root_scope**。
- **函数定义点**：将闭包变量**绑定**到闭包作用域中。
  （Sema 已收集显式捕获列表，见 ADR-001）

### 2. 绑定 = 共享，不是复制

- 绑定的是 **value（共享同一个 value 对象）**，不是复制。
- 闭包作用域加入这些 value 时 **scope_ref++**，与定义作用域共同持有。
- 因此修改一方，另一方可见（符合 JS 闭包共享变量语义）。

### 3. 函数孤立化

- 运行时查找变量只需：closure_scope → root_scope → global。
- **不再依赖定义时的中间词法作用域链**。
- 每个函数是「孤立」的，不运行时依赖词法所在作用域。
- 自然解决：定义函数的作用域已销毁，闭包变量仍被闭包作用域持有（保活）。

### 4. 闭包作用域创建时机：每次定义都新建

- 每次执行到函数定义（函数表达式求值、函数声明执行）都创建新的闭包作用域并绑定。
- 符合 JS「每次定义生成新闭包」语义。

### 5. 函数调用时的三层作用域

```
closure_scope（持久，随函数对象释放；闭包变量）
  ↑ parent
argument_scope（临时，存放实际参数；调用开始创建）
  ↑ parent
body_scope（临时，实际执行函数逻辑；局部变量）
```

- **closure_scope**：生命周期持久，随函数对象释放而释放。
- **argument_scope**：调用开始时临时创建，存放实际参数。
- **body_scope**：parent=argument_scope，实际执行函数逻辑的作用域。
- **作用域析构时递归释放子作用域**：
  函数退出销毁 argument_scope 时，body_scope 一并释放。

## 作用域链查找

```
函数运行时查找变量：
  body_scope → argument_scope → closure_scope → root_scope → global
```

## 后果

- 优点：函数孤立、闭包保活自然、无运行时词法链依赖、符合 JS 语义。
- 缺点：每次函数调用创建两个临时作用域（有开销）；闭包变量需定义点绑定。
